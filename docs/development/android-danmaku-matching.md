# Android TV 弹幕自动匹配与交互验证

此页记录 `6176ce5` 前一阶段；当前顺序优选、暂定阈值与60 FPS目标验证见 [后续记录](danmaku-progressive-60fps.md)。

2026-11-17，基于最新 main `2791ff2`。仅修改 Android TV 和必要 Core 纯逻辑；四源去广告、Media3 和 MediaTimeline 保持原有职责，无新增依赖、服务或数据库。

## 自动匹配与记忆

- 手动偏好只保存 animeId，SharedPreferences 身份是服务地址（含 Token 路径）＋workId＋site 的长度编码摘要。切线路、切集复用；换作品、资源站、服务实例隔离，不兼容旧实验键。服务地址另由既有配置保存，日志不输出地址或 Token。
- 首先直接获取保存作品的集数和评论；成功无需搜索。无偏好或失效时搜索标题，排除不同标题、季度、已知不同年份的候选。年份只用现有资源站详情，不请求外部元数据。
- 优先 episodeNumber 的语义值，支持阿拉伯/中文集号和 S02E03 等标签；结合 seasons/seasonId，拒绝未知多季度、重复集号和特别篇/番外/加更等歧义。没有可信集号时手动选，不以数组顺序代替。
- 候选缺集、滚动评论为空、请求失败或超时后回退。最多三候选，单候选8秒、整体30秒；先得到合理的有效结果即显示。最多约七个客户端 API 请求，成功偏好通常两个；均后台执行，不阻塞视频。
- 自动匹配和回退均不保存选择；只有点击作品芯片才写入偏好。手动点击“匹配”重新搜索完整候选，避免被已有偏好提前截断。
- 上游搜索没有统一弹幕数量字段；只使用本会话已获取的评论数量辅助同等候选排序，最多缓存三个已获取 track，不为比较数量下载全部候选。服务变化立即清空旧 ID、评论和待处理请求。

## 界面与时钟

快捷菜单：开关 → 提前 1 秒 → 延后 1 秒 → 弱化且不可聚焦的累计偏移 → 选择弹幕。已有有效滚动弹幕时默认聚焦开关，否则聚焦选择；返回回到弹幕按钮。正偏移表示弹幕提前，提前/延后分别加/减1000毫秒。

选择弹窗依次为作品名称与匹配、来源、剧集（可定位当前集）、次级 API 地址与保存。保持 TV Material 3/SelectionChip；输入框聚焦不弹键盘，确认进入编辑；偏移仅在快捷菜单提供。

Canvas 保留单循环、排序游标、Seek 二分重建、四轨/12条上限和实际视频上方1/4区域。原碰撞判定同时检查入场与前条退场时的间隔，线性运动在两端都分离时不会中途追尾；本轮没有另建排版引擎，抽查画面未发现需要修改的碰撞错误。实测软件渲染开销后，将连续重绘请求限为约30fps；滚动位置继续直接取 Media3 时间，不累计动画时间。暂停/缓冲不持续推进，关闭停止连续绘制。

过滤后时间已经是有效播放时间，不重复减广告；只在已确认参考映射存在时转换，再应用一次手动偏移。无共同剧情锚点时仍不能保证跨版本语义同步。服务端偏移不重复计算。

## 上游契约核对

核对 huangxd-/danmu_api `619612b896f1a83b39a34d7e0775bf1711d0e45b` 的 models/dandan-model.js、worker.js、apis/dandan-api.js 和 utils/offset-util.js：

- search/anime、bangumi/{animeId}、comment/{episodeId}；地址中的 Token 前缀保留，animeId 与 episodeId 分开使用。
- source 是弹幕来源，不是影视首播平台；没有平台人工优先表。
- episodeNumber 为字符串，seasonId 关联 seasons 的 id/name；新增 Core 解析回归。
- videoDuration 单位为秒，转毫秒仅一次；评论 p 的时间/模式/颜色按既有解析处理，客户端只绘制普通滚动模式。
- 服务端已应用单源/聚合偏移；不重复服务端聚合、去重或过滤。独立分段式响应尚未扩展，本轮真实样本均为平铺 comments。

## 实际验证

使用独立 `.adprobe` 包，不覆盖日常应用与其数据。Android 14 TV arm64、1080p；原图形后端发生 ColorBuffer 崩溃，随后改用 swiftshader、关闭 Vulkan、冷启动测试。局域网9321端口本轮连接失败，使用用户配置的公共 HTTPS 服务成功，未改部署。

1. Core JVM 75项、Android 单元测试44项与 debug APK 编译通过。回归包括标题/季度/年份/特殊集、缺集/空评论/失败回退、自动不写偏好、手动重搜、评论缓存、服务变化失效和偏好身份隔离。
2. 两个真实 Media3＋模拟接口的遥控器测试通过：无数据默认聚焦选择、开关、偏移正负显示、逐集开关保存、来源焦点缩放留白，以及聚焦不弹键盘/确认编辑/返回关闭。
3. 真实《逐玉》第1集暴风 HLS＋真实服务自动加载13,380条滚动评论；随后通过实际选择界面选腾讯来源，加载42,284条。真实响应约4.03MB。自动流程优先快速非空结果，不声称一定选择最多评论的来源。
4. 42,284条样本已验证暂停冻结、Seek 后重建、1.5×和2×媒体时钟一致、实际画面滚动和开关对照。截图抽查显示文字位于实际画面上方，长短混排无明显覆盖。未做实体电视人工视听/剧情语义验收。

5. 补充真实《逐玉》前两集联合播放测试通过：正偏移+1000ms只应用一次；观察到真实缓冲并验证弹幕时钟冻结；关闭停绘、切集清除旧评论、错误 API 路径下视频持续推进均通过。连续60秒检查无新增解码丢帧，PSS约76–201MiB波动并被GC回收。仅为短测，不是长期泄漏结论。

### 性能对照

相同120秒场景，每段约20秒，关闭→开启→关闭，评论预先加载。CPU 是应用进程CPU/墙钟（100%为一个核），不是整机占用；遥控器值是派发与主线程回执，不是光学端到端延迟。初版使用 Compose 空闲等待的数据被排除，最终采样使用主线程回执。

| 状态 | CPU | UI帧耗时P95 | 解码新增丢帧 | 按键回执最大耗时 |
|---|---:|---:|---:|---:|
| 原连续重绘，开 |64.83%|89.41ms|0|121ms|
| 限频后，关 |7.02%|无足够UI样本|0|8ms|
| 限频后，开 |24.66%|33.72ms|0|21ms|
| 限频后，再关 |7.41%|仅1帧，不作统计|0|10ms|

限频后开启段PSS约194→145MiB，随后关闭段约149→113MiB，有GC波动；短测不能证明没有长期泄漏。FrameMetrics 不包含 SurfaceView 独立解码帧，不能把关闭弹幕时UI无帧当作视频无帧。单次软件图形模拟器对照不能推广为实体电视性能结论。数据见 [性能记录](android-danmaku-performance-2026-11-17.json)。

## 复现

```bash
./gradlew :core:jvmTest
./AndroidTV/gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest
```

仪器测试入口：`PlayerRemoteTest` 两个 danmaku 方法；`DanmakuPerformanceTest` 使用 media_url、danmu_url、work_title、media_site 参数，可传 manual_title_id 检查较大真实评论集。`LiveDanmakuPlaybackTest` 保留真实切集、偏移和接口失败验证入口。URL/Token 通过本机私有参数注入，不写入仓库。

仍需人工确认：不同参考版本的实际剧情语义同步、实体电视主观流畅度与音画质量。稀有标题别名、没有可信季度/集号的特殊篇需手动选择；慢候选可能因8秒预算被跳过，仍可手动加载。没有新增广告规则，也没有将测试中的固定 ID、位置或地址写入生产逻辑。
