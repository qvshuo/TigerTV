# Android TV 弹幕

生产路径为 `PlayerScreen → DanmakuState / DanmakuPlayback → DanmakuClient`，Media3负责播放，单Canvas负责绘制。没有新增服务、数据库或识别模型。

## 使用与匹配

弹幕按钮在倍速右侧，菜单为开关、提前1秒、延后1秒、当前累计偏移、选择弹幕。时间校准只在快捷菜单提供。选择弹窗保留作品搜索、来源和剧集；未配置时提供“前往设置”。输入框确认后编辑；未编辑时方向键用于导航，完成编辑后不清空焦点。来源使用逐项惰性列表，弹窗遵守48dp/28dp电视安全边距。在独立设置页明确保存 API 地址；草稿不参与搜索。保存后重新匹配当前作品，API 失败不影响视频。

手动偏好按服务地址＋workId＋site保存animeId，不区分线路/集数；只有成功加载当前集有效滚动评论后才保存。自动匹配、回退和替换不改写偏好。开关按播放进度的作品/资源站/线路/集数粒度保存，偏移限当前会话。

优先有效手动偏好。自动匹配比较规范标题、明确别名、年份及季度，再用原始集名、语义集号和日期核对正片。年份缺失的候选排在明确一致之后。同组内先探测爱奇艺、优酷、腾讯、芒果，再探测其他来源。首份有效评论立即显示；同组新来源的滚动评论数量达到当前两倍，且参考时长差不超过 max(30 秒, 2%) 时替换。原关键词找不到有效评论时，至多用规范化关键词再查一次。缺集、空评论、失败继续回退；最多12个业务API调用/60秒，每候选20秒，最多缓存三份track。429停止本轮。

关闭只取消正在进行的自动匹配/比较，不清空来源和评论；再次开启有数据则直接恢复，无数据则重新匹配。手动选源/选集会取消自动优选，但其显式请求不会因开关而误取消。切播放会话或API服务取消旧请求，退出会话取消全部请求。只有一个请求Job。

## 绘制与时间轴

活动弹幕调用`postInvalidateOnAnimation()`，随设备刷新绘制，不设置固定FPS或降频控制。暂停/缓冲停止连续绘制，空窗按下一条评论时间及Media3倍速定时唤醒，关闭/释放取消唤醒。

完整评论保留；已排序游标只处理当前窗口，Seek后二分定位。实际画面上方 1/4、最多四轨/12 条，22sp 字号和 2dp 描边。首次加载且没有可显示评论时在该区域居中提示；按真实文字宽度、入场距离和离场前追尾条件接纳条目，拥挤时跳过本窗口放不下的评论，不做全片数量截断。文字宽度缓存256项，不逐帧扫描、排序或测量全部评论。

位置取Media3真实时间。过滤后的播放时间已经去掉广告，不再扣广告；有已确认参考映射时转换，否则使用播放时间加一次手动偏移。参考时长接近不保证剧情版本一致，固定偏移不能修复中途剪辑差异。

## 验证入口与调查

日常执行Core JVM和Android单元测试及APK编译。保留匹配/回退、2倍替换、偏好范围、取消/恢复、429、服务变化测试，以及遥控器和真实Media3的暂停/Seek/倍速/空窗回归。

`LiveDanmakuPlaybackTest`是按需实网入口：显式传入`media_url`、`next_media_url`、`media_site`、`work_title`、`danmu_url`。可选 `danmu_title_id` 用于复现已保存手动偏好，`danmu_episode_id` 用于核对返回集号，`soak_seconds` 用于短时连续播放采样。无服务或媒体地址时跳过，不作为日常修改的强制项。真实媒体、令牌和评论只留本机；不再维护旧限帧策略的性能对照测试。

保留[三部作品调查原始统计](../../experiments/danmaku/survey-2026-11-17.json)及同目录样本和离线复现工具：2026-11-17快照中，嫁金钗两入口18,889条但均为同一优酷内容；逐玉腾讯42,288条、爱奇艺13,381条，约3.16倍；后会友期正片23,620条，没有第二个可比来源。数据会变化、重复入口不能当独立平台证据，调查未设置DANMU_LIMIT。

四源去广告保持原实现。[24份清单统计](../../experiments/hls-ad/four-source-current-2026-11-16.json)记录58组已确认素材、1117.656秒；该样本结果不代表全站覆盖率。[原真实联合播放证据](../../experiments/hls-ad/android-danmaku-playback-2026-11-16.json)及独立HLS研究继续保留，未因清理FPS实验而删除。

当前重点来源及播放验收范围见[Android TV重点来源](android-tv-sources.md)。

Android 14 TV 模拟器在默认 960×540dp 下通过遥控器和弹幕回归。640×360dp 配合 1.3 倍字体时，首页、搜索和设置的返回焦点及弹幕选择回归也通过。实体电视音画和长时间播放仍需验收。


2026-11-19 补测：真实服务重新返回《嫁金钗》优酷和 360 入口各 18,898 条，两入口未触发换源。《逐玉》爱奇艺返回 13,378 条。继续探测遇到 HTTP 429，生产客户端按预算停止。对历史真实响应重跑当前 Core，《逐玉》腾讯 42,288 条与爱奇艺 13,381 条满足同组 2 倍和时长条件，《后会友期》按日期加期号匹配正片，沉浸版和抢鲜版没有自动匹配。后续定点实网请求也匹配到 2026-10-22 第 1 期正片，共 18,641 条滚动评论。

真实联合回归使用 Android 14 TV 模拟器、360《逐玉》第 1 集与现有弹幕服务。验证已保存偏好加载、13,378 条弹幕数据、暂停/缓冲冻时、Seek、1.5 倍速、加秒校准、切集及 API 失败回退。连续播放 90 秒推进 135.008 秒，解码累计 3,652 帧、0 丢帧。播放过程 PSS 样本约 129–148 MiB，三次短 CPU 样本为单核的 16%、57%、40%。这些是模拟器读数，不代表电视硬件性能或人耳音画验收。

2026-11-20 定点回归使用 360《后会友期》「第20261119期下」。同一天的上、下分别匹配，API 的列表序号不参与判断。模拟器实际自动匹配并绘制 11,789 条滚动弹幕中的当前窗口，参考片长 79:05。暂停、缓冲、Seek、1.5 倍速、偏移和切集验证通过。单独的 Media3 回归验证先渲染视频首帧，再显示仍在等待的弹幕加载提示。


详情焦点对照使用同一模拟器、120 集夹具和每轮 36 次方向键，两版各三轮。三轮中位数的按键派发 P95 为 221→82ms，应用帧耗时 P95 为 250→117ms，均达到第 34 集并回到资源区。按键派发计时不含完整按键到画面延迟，模拟器掉帧比例仍高。可在 `DetailSourceScrollTest#rapidEpisodeNavigationKeepsFocusInLongLists` 加 `-e measure_episode_focus true` 查看 `TigerTVEpisodeFocus`。


日期型上下篇以日期和明确分段匹配。例如 360「第20261119期下」可对应「第6期下… 2026-11-19期」。上篇、抢鲜及沉浸等版本分别核对。播放只使用后台准备的普通弹幕列表，首帧出现之后才显示画面内的弹幕加载提示。
