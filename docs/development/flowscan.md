# DDYS FlowScan 静态研究

检查 FlowScan 1.0.0 公开发布树 `91d917875755a68f04ce4cc5bee3bb10832cf5b6`。研究只读取 `manifest.json`、`content.min.js`、`background.min.js`、`inject.min.js`，在临时目录格式化并还原字符串表。网站只用于确认目标场景。该发布树未声明明确的开源许可证，TigerTV 仓库未引入其脚本或反混淆产物。 [FlowScan 发布树](https://github.com/ddysdev/flowscan-/tree/91d917875755a68f04ce4cc5bee3bb10832cf5b6) · [DDYS](https://ddys.io/)

| 已证实的机制 | 静态证据 |
|---|---|
| 注入与拦截 | Manifest V3 在 DDYS 页面及匹配 iframe 的 `document_start` 注入 content script，后者加载页面级脚本并转接深度探测消息。页面脚本包含 `fetch`、`Response.text`、XHR `open` 与响应 getter 的拦截，以及 hls.js Loader 和 Worker 路径。异步 fetch 可替换响应正文，XHR 响应 getter 有同步处理路径。Worker 钩子可将命中的文本发回主线程，原 fetch 响应仍返回。 |
| 清单识别 | 主清单跳过。媒体分片读取 `EXTINF`、相对 URI 解析后的地址、文件名、主机变化、`DISCONTINUITY`，并记录 SCTE35/CUE 及广告型 `DATERANGE` 标记。把断点分组，再将短组、时长分布、路径及主机等线索合成分数。只有归为强广告的组进入删除集合。仅一个分组的主处理路径保留原文。 |
| 深度探测 | 后台批量向部分可疑组与正常组样本发 HEAD，非成功响应再试 `GET Range: bytes=0-1`。返回 Last-Modified、Content-Length、ETag、Server 和 Date。已追到的决策读取并比较 Last-Modified。读取 Content-Length 和 ETag 本身不足以证明其参与分类，也未确认 Range 分支用 Content-Range 恢复完整对象字节数。 |
| 改写与缓存 | 跳过目标分片的 EXTINF 与 URI，处理拼接点的 DISCONTINUITY 并合并重复标记，清理清单首尾多余断点。有按清单 URL 的结果缓存。静态检查未确认它为所有加密、隐式 IV、独立音轨、滑窗或媒体序列号场景重建清单状态，也无法推断线上首帧开销或全站误删率。 |

## TigerTV 通用识别

Android TV 的 Media3 DataSource 与 Web 的 hls.js 实例级 `pLoader` 从当前响应检查完整 VOD。两端共享阈值和夹具，按以下证据判断：

- 成对 CUE-OUT / CUE-IN，分片累计时长与声明吻合。
- 广告词出现在连续分片路径中，两侧为常规内容。两侧同属一个 URI 家族，或广告组有成对断点。
- 同一明文组的分片路径和逐片时长在当前清单中重复，前后有足够的加密正片。边界可来自密钥状态变化，也可来自断点。

单个候选为 5–60 秒。通用启发式使用 15% 的总删除量预算，经过来源级指纹确认的段落可超出这个预算。规则使用已有的清单响应。旧单集完整 URI 指纹仅保留作历史回归参考。 [共享参数](../../shared/hls-heuristics.json) · [样本](../fixtures/hls-smart.sample.json) · [历史指纹](../fixtures/hls-retired-fingerprints.sample.json)

改写保留密钥、分片 URI 和保留分片的原始隐式 IV 语义，合并连续广告区间，在新接缝插入断点。续播以原始时间保存，恢复时映射到有效时间。弹幕直接使用实际播放时钟。独立轨道、多变体、直播、MAP、BYTERANGE、DRM 和无法安全改写的标签保留原样。 [HLS 变体时间轴约束](https://datatracker.ietf.org/doc/html/rfc8216#section-6.2.4)

## 无标记插播和指纹评估

360《逐玉》首集的已验帧 26.400 秒插播有连续编号与连续时间戳，前后同目录，并沿用同一 AES-128 密钥和 IV。此前采样中，广告和相邻正片均为 H.264 High、1920×804、44.1 kHz 双声道 AAC-LC，广告码率范围落在正片范围内。两侧均有 Last-Modified 和 ETag。当前通用规则会保留该段，仍可识别同集三组共 52.701 秒的重复明文广告。历史爱奇艺只有单组、无明确广告路径的 17.567 秒样本也在当前规则下保留。

HTTP 头、分片时长和编码参数在这些边界缺乏可靠区分度。跨集比较可用于验证是否复用相同素材。实际过滤维持清单内证据，避免跨集预取、下载待判分片或在播放位置已经建立后更换时间轴。

## 独立抽样

用《嫁金钗》《藏海传》《朝雪录》《以法之名》《生万物》的前两集抽查了 44 份真实清单。涉及 360、光速、红牛、爱奇艺、非凡五个源键。规则在 360 的 8 份清单中识别 24 个 17.567 秒窗口，另外 36 份未命中。抽帧确认 4 部作品的候选包含相同的广告画面，抽取的对应分片逐字节相同。实际播放器另验证了 360 播放接缝。样本没有逐帧全量标注，命中数不能推算召回率或整片误删率。

44 份清单均未出现《逐玉》26.400 秒插播的完整时长序列。没有取得证据表明它可以通过跨集复用直接定位。对这些样本本地重复执行 Web 清单处理，中位数约 0.50 毫秒、P95 约 1.23 毫秒，未计入网络与首帧。样本没有多变体、MAP 或 BYTERANGE，继续使用已有的兼容回退。

## 来源级指纹与复跑

新增来源级规则使用解析后媒体清单的 CDN 主机、片段路径形状、逐片时长和断点。爱奇艺要求 `/videos/` 正片夹住 `/stream/` 明文组。魔都要求 `10137kb/hls` 中的同一组素材重复出现，允许片尾。360 补充识别重复的绝对地址广告组与相对地址正片的结构，可处理正片也是明文的清单。规则没有按作品、集数、完整 URI 或固定时间点配置。 [共享规则](../../shared/hls-heuristics.json) · [共享正反例](../fixtures/hls-source-groups.sample.json)

同一批复跑中，爱奇艺 16/16 份命中 16 组（其中 8 份为独立样本），魔都资源 8/8 份命中 28 组，360 8/8 份命中 23 组。魔都动漫返回的《逐玉》两份与魔都资源相同，不计为独立样本。光速、红牛和非凡的 22 份清单保持原样。对独立的《藏海传》实际抽帧，爱奇艺和 360 候选内均是博彩广告，前后分片为正片。魔都的新作品搜索本轮返回 502，暂时只验证原有四部跨作品素材。这些是清单命中结果，整片广告召回率仍需完整标注。

360《逐玉》已知的 26.400 秒同目录、同密钥插播仍保留。未见到独立作品使用相同结构边界，未把单集特征写入规则。

Chrome 在 18817 实播跨接缝，爱奇艺《逐玉》删 17.567 秒，魔都《逐玉》删 87.840 秒。360《藏海传》的浏览器检查复用了已获取的真实媒体入口，CDN 清单与分片仍为直连，跨接缝实播时删除 52.701 秒。Kotlin 与 TypeScript 在同一批 56 份真实媒体清单上给出完全一致的过滤区间。

非凡的博彩插播由五个明文分片组成，前后都有断点，组内恰好还有一个断点。非凡规则要求 CDN 主机、分片路径形状、完整的五片时长序列、前后正片及断点位置均符合。片名、集数、播放时间和完整 URI 均未进入规则。共享夹具验证两个组内断点位置、其他主机和仅时长吻合的清单。另有真实响应在结束标记后带有残缺 URI 和完全相同的断点及末片，两端只在匹配这类重复尾部时忽略副本。 [实测记录](android-tv-sources.md#非凡跨作品复验)
