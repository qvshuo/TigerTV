# DDYS FlowScan 静态研究

检查 FlowScan 1.0.0 公开发布树 `91d917875755a68f04ce4cc5bee3bb10832cf5b6`。研究只读取 `manifest.json`、`content.min.js`、`background.min.js`、`inject.min.js`，在临时目录格式化并还原字符串表。网站只用于确认目标场景。该发布树未声明明确的开源许可证，TigerTV 仓库未引入其脚本或反混淆产物。 [FlowScan 发布树](https://github.com/ddysdev/flowscan-/tree/91d917875755a68f04ce4cc5bee3bb10832cf5b6) · [DDYS](https://ddys.io/)

| 已证实的机制 | 静态证据 |
|---|---|
| 注入与拦截 | Manifest V3 在 DDYS 页面及匹配 iframe 的 `document_start` 注入 content script，后者加载页面级脚本并转接深度探测消息。页面脚本包含 `fetch`、`Response.text`、XHR `open` 与响应 getter 的拦截，以及 hls.js Loader 和 Worker 路径。异步 fetch 可替换响应正文，XHR 响应 getter 有同步处理路径。Worker 钩子可将命中的文本发回主线程，原 fetch 响应仍返回。 |
| 清单识别 | 主清单跳过。媒体分片读取 `EXTINF`、相对 URI 解析后的地址、文件名、主机变化、`DISCONTINUITY`，并记录 SCTE35/CUE 及广告型 `DATERANGE` 标记。把断点分组，再将短组、时长分布、路径及主机等线索合成分数。只有归为强广告的组进入删除集合。仅一个分组的主处理路径保留原文。 |
| 深度探测 | 后台批量向部分可疑组与正常组样本发 HEAD，非成功响应再试 `GET Range: bytes=0-1`。返回 Last-Modified、Content-Length、ETag、Server 和 Date。已追到的决策读取并比较 Last-Modified。读取 Content-Length 和 ETag 本身不足以证明其参与分类，也未确认 Range 分支用 Content-Range 恢复完整对象字节数。 |
| 改写与缓存 | 跳过目标分片的 EXTINF 与 URI，处理拼接点的 DISCONTINUITY 并合并重复标记，清理清单首尾多余断点。有按清单 URL 的结果缓存。静态检查未确认它为所有加密、隐式 IV、独立音轨、滑窗或媒体序列号场景重建清单状态，也无法推断线上首帧开销或全站误删率。 |

TigerTV 借鉴对清单结构、候选边界和分段结果的显式处理。Android TV 的 Media3 DataSource 与 Web 的 hls.js 实例级 `pLoader` 消费同一个 [规则定义](../../shared/hls-ad-rules.json)。匹配依赖站点、完整 URI 指纹数组、每片精确时长和断点边界。过滤沿用请求自身的响应与 URL，只替换清单文本，浏览器按原地址请求分片和密钥。整条路径省去额外 HEAD、Range、清单预取和全局网络钩子。见 [Video.js 10 HLS 适配](https://videojs.org/docs/framework/html/reference/components/hlsjs-video)。

改写限定于完整 VOD。支持明文和 identity AES-128。删除造成编号移动时，按保留分片原始媒体序列生成显式 IV。保留有效密钥变化、分片 URI、媒体序列声明和必要断点。清单压缩后的有效时间映射回原始进度，弹幕使用播放时钟的有效时间。相对地址由 HLS 适配器按最终响应 URL 解析。独立音轨、多变体、直播、BYTERANGE、MAP、DRM 和未知标签保留原清单。魔都规则只限魔都资源。共用样本断言输出清单、原始过滤区间和加密状态。 [共享夹具](../fixtures/hls-filter.sample.json)

360《逐玉》第 1 集的历史样本已实地抽帧确认仍有约 26.40 秒插播，位于已过滤时间约 960.16–986.56 秒。插播和相邻剧情同目录、连续编号、连续时间戳、采用同一 AES-128 结构且没有断点。组结构和 HTTP 头无法独立区分这里的商业段与剧情。此前因缺少可复核的素材身份而保留该段。 [Android 真实来源抽查](android-tv-sources.md)


## TigerTV 启发式

Android TV 与 Web 先匹配当前来源的精确规则，再对所有可解析的完整 VOD 检查三类候选。精确规则名单与启发式入口独立。

- 成对 CUE-OUT / CUE-IN，逐片时长和声明时长一致。允许在连续编号、相同目录和同一密钥下定位边界。
- 短组的路径有明确广告词，两侧至少三片回到同一内容 URI 家族。单纯切域名、极短分片或断点不足以删除。
- 同一明文片组的 URI 序列和逐片时长至少重复两次。前后由加密正片划界，可在清单末尾结束。边界可以是密钥状态变化，因此支持没有 `DISCONTINUITY` 的清单。

候选组为 5–60 秒，启发式与已知时长合计不超过整集的 15%。规则使用当前清单已有的结构、地址和加密状态。HTTP 响应头和媒体包时间戳只用于离线佐证，播放加载器沿用同一次清单请求。没有广告证据时，同目录中的短剧场、插曲和自然转场继续保留。 [共享样本](../fixtures/hls-smart.sample.json)


2026-11-20 重新取得 360《逐玉》第 1 集的媒体清单，浏览器在 955 和 993 秒抽帧为剧情，在 964、974 和 983 秒命中有广告标记的促销窗口。当前和留存的同版清单有相同的连续 13 个分片，原始区间为 960.160–986.560 秒，前后沿用同一显式 AES-128 密钥和 IV。新增该素材的完整 URI 指纹与时长向量。只有已验证的连续组可绕过断点要求，未知同目录片段仍走启发式判定。

该响应的旧精确规则去掉 52.701 秒。用启发式单独复跑，可识别同一组三次出现的明文插播，总计也是 52.701 秒。加入已验帧的连续组后，同一响应共去掉 79.101 秒，清单有效时长从 2868.160 秒缩至 2841.760 秒，接近同集红牛参考切片 2841.750 秒。这能支持剪接效果核对，不能推断任意弹幕来源与视频全程对齐。

Android TV 在同一轮实际 CDN 播放测试验证每条有后续正片的接缝，Firefox 和 WebKit 实放跨越 960.160 秒新接缝。360 的真实清单在本机 20 次热运行中 Web 改写中位数为 1.49 ms，这个数字不包含请求或首帧时长。广告窗口及其邻接画面抽查没有发现正片误删。共享反例“只有断点和短时长的章节”仍保留。更大来源集合的误删率、烧录角标以及无可验证标记的插播仍需独立抽样。

Go Gateway 迁移时重新抽样《逐玉》前两集，取得 8 个源键的 16 份真实媒体清单。样本均为 TS，主清单最多包含一条变体，样本未出现 MAP 或 BYTERANGE。360 首集仍过滤 79.101 秒，三个有后续正片的接缝为有效时间 960.160、1453.280、2808.840 秒，本轮 Chrome 实播跨过三处。同一真实清单移除站点精确规则后，通用启发式可识别三组共 52.701 秒。爱奇艺首集的精确规则移除 17.567 秒，其余样本未新增命中。

离线解码比较 26.4 秒插播中的 10 个分片和相邻正片 18 个分片，两侧均为 1920×804 H.264 High 与 44.1 kHz 双声道 AAC-LC。插播约 154–324 kB/s，落在抽样正片约 78–482 kB/s 的范围内。两组响应都有 Last-Modified 和 ETag，单用这些特征不足以定位广告边界。客户端继续只读既有清单。同目录、连续编号、同密钥又没有其他证据的未知内容仍保留。 [HLS 的变体时间轴约束](https://datatracker.ietf.org/doc/html/rfc8216#section-6.2.4)
