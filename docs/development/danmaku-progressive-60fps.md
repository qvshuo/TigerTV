# Android TV 顺序弹幕优选与60 FPS目标

2026-11-17，基于最新 main `6176ce5`。只修改 Android TV 和必要 Core；未修改 macOS、Media3内核、四源广告规则或 MediaTimeline。没有新增依赖、服务、数据库或全片评论截断。

## 阈值与渐进替换

暂定 **新 mode 1 数量 ≥ 当前的2倍，且绝对增加 ≥1000条**。仅《逐玉》提供了独立平台间的有效对照，不能从三部作品推导统计上稳定的阈值。2倍是区分重复入口1.0倍与显著差异3.16倍的保守暂定规则，1000条用于排除小样本变化，不声称是统计拟合出的最佳值。

额外要求两份参考时长均已知，差异不超过 max(30秒,当前时长的2%)；未知或差异过大不自动替换。数量和时长都不能证明剧情版本一致，仍可能需要手动校准。

自动流程：先尝试当前服务/作品/资源站的手动偏好；有效则停止。否则按标题/季度/年份及语义集号筛选，顺序探测爱奇艺→优酷→腾讯→芒果→其他来源。第一份有效评论立即发布，后续达到阈值才发布替代track。最多12个业务API调用、60秒总预算、20秒单候选预算；不固定截断前三项、不并发下载候选。保留当前有效结果直至下一份加载成功，失败或预算结束不影响已有弹幕。

最多复用三份评论缓存。替换只修改 DanmakuState 中选源/选集/track，不重载 Media3、不修改播放位置、不再次减广告，也不修改用户累计偏移。手动操作取消旧任务；切服务、切播放会话取消旧任务。只有手动来源当前集成功取得有效 mode 1 后才持久化 animeId；失败、空评论和自动替换均不写偏好。

实网仪器测试捕获：13,381条首先显示，约1.87秒后替换为42,288条，播放器对象和媒体条目未改变，时间未倒退。单元测试验证了有首份数据时仍在后台顺序比较、偏移保留、手动取消待返回结果、有效偏好不扫描其他来源及第五个候选可达。

## 渲染与局部容量

保留单 Canvas、排序评论游标、Seek 二分重建和原8秒媒体过屏时间。Core评论已排序，绑定时只过滤支持模式；不因60 FPS重新解析/排序或每帧测量文字。256项宽度缓存复用重复文字；每条轨道只检查最后接纳的一条，去掉筛选活动数组的临时分配。等过屏寿命下，已接纳条目不互相超越，因此新条目只需保持在最新条目之后。

轨道数 `clamp(floor(实际画面高度×1/4 ÷ (字号像素×1.5)),1,4)`；并发最多12条。对新条目按实际宽度判断入场间隔，以及前条离场时新条的位置：两端安全则整个线性运动区间安全。长短文字速度为 `(画面宽度+文字宽度)/8秒`，不允许途中追尾。拥挤时只跳过本窗口无法接纳的条目，完整评论仍保留。

观察性容量估算：`每分钟 ≈ 轨道数×60×(画面宽度+已接纳平均文字宽度)/(8×(平均文字宽度+安全间距))`。真实密集窗口为2轨，估算约82条/分钟；20秒内到达333条，接纳21、空间不足跳过312，画面平均约8.6条、观察峰值10条。它不是全片截断阈值，低密度窗口自然接纳更多。

活动时默认 `postInvalidateOnAnimation()`，以60 FPS为目标。Window FrameMetrics 总帧耗时的指数均值（系数0.2）连续三次高于22ms，改为帧调度延迟32ms让步；暂停、空闲或窗口重建后重新尝试。只在有可见弹幕时运行连续帧循环；空窗按下一条媒体时间和当前倍速定时唤醒。暂停/缓冲停钟、Seek/源替换重建、关闭/释放取消唤醒和帧观察。

试验过文字位图缓存，但在当前设备未测得独立CPU收益，因此已删除；最终只保留原生文字绘制和小型宽度缓存。

## DANMU_LIMIT 核对

核对 huangxd-/danmu_api `619612b896f1a83b39a34d7e0775bf1711d0e45b` 的 configs/envs.js 与 utils/danmu-util.js：0表示不限制；正值单位为千，对经服务端过滤、去重及点赞处理后的整份结果按均匀索引采样，随后还有模式/颜色转换。它不是轨道密度控制。研究和自动比较没有设置全量限制，客户端不重复服务器去重、过滤和偏移。

### 后续复测与真实限制

后续运行整理后的调查工具时，优酷两入口均返回18,875条、腾讯42,286条，其他三条遇HTTP429。数量存在小幅动态变化，429没有被当成空弹幕；完整首轮快照与后续失败均保留。客户端现遇429停止本轮继续探测并保留已有有效结果，工具也停止后续请求并记录状态，不修改或绕过服务限制。该限流回归以HTTP状态夹具测试，没有继续用实网撞限流。

真正影响使用的剩余限制：只有一部作品的独立平台对照支持暂定阈值；服务限流/超时可能提前终止优选；季度、综艺拆分或无可信集号时需要手动选择；参考时长接近不能证明剧情完全对齐；实体电视60 FPS与主观音画仍待人工验证。

### 代码与复现入口

- `DanmakuState.kt`：顺序预算、首份发布/渐进替换、取消、成功后记忆、429停止。
- Core `DanmakuSelection.kt`：探测顺序与单一暂定阈值；`DanmakuMatching.kt`：真实集号冲突与特别内容排除。
- `DanmakuView.kt`：现有容量计算、末尾轨道碰撞、宽度缓存、空窗唤醒和帧预算退让。
- `DanmakuPlayback.kt` / `PlayerScreen.kt`：保存后的服务配置和搜索，保留原菜单及时间轴职责。
- `DanmakuPerformanceTest`：真实服务或显式缓存评论模式，记录FPS/帧耗时/CPU/PSS/密度；`DanmakuRenderTest`：真实Media3空闲时钟夹具；原有Live与遥控器测试继续复用。
